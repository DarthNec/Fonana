## 📋 Задача

Проанализировать и предложить варианты **софт-регистрации** (упрощённой) для пользователей без подключённого кошелька:

### Требования:
- ✅ **Без email** - максимально простая регистрация
- ✅ **Защита от абьюза** - нельзя обойти через очистку cookies/cache
- ✅ **Максимальная простота** - минимум шагов для пользователя
- ✅ **Несколько вариантов** - solution matrix с оценками

---

## 🔍 Текущая система аутентификации

### 1. **NextAuth** (GitHub Provider)
```typescript
// lib/auth.ts
providers: [
  GithubProvider({
    clientId: process.env.GITHUB_ID!,
    clientSecret: process.env.GITHUB_SECRET!,
  })
]
```
**Проблема:** Требует GitHub аккаунт (email)

---

### 2. **Solana Wallet Auth** (основной метод)
```typescript
// app/api/auth/wallet/route.ts
POST /api/auth/wallet

// Флоу:
1. Пользователь подключает Solana кошелёк
2. API ищет user по wallet address
3. Если не найден → создаёт нового:
   - wallet: publicKey
   - nickname: `user_{первые8символов}`
   - solanaWallet: publicKey
4. Генерирует JWT token (expires: 30 days)
5. Возвращает token + user data
```

**Преимущества:**
- ✅ Без email
- ✅ Криптографическая подпись
- ✅ Уникальный идентификатор (wallet address)

**Недостатки:**
- ❌ Требует установку кошелька (Phantom, etc)
- ❌ Высокий порог входа для новичков
- ❌ Многие пользователи не знают что такое Web3

---

### 3. **JWT Token System**
```typescript
// lib/utils/jwt.ts
class JWTManager {
  - getToken(): string | null
  - setToken(token: string): void
  - clearToken(): void
  - scheduleRefresh(): void
}
```

**Хранение:** `localStorage.getItem('fonana_jwt')`  
**Lifetime:** 30 дней  
**Refresh:** Автоматический через `scheduleRefresh()`

## 🎯 Проблема

**Текущая ситуация:**
- Пользователи без кошелька **НЕ МОГУТ** зарегистрироваться
- NextAuth требует GitHub (email)
- Wallet auth требует Web3 знания

**Цель:**
- Дать возможность пробовать платформу **БЕЗ** кошелька и email
- **НО** с защитой от абьюза (множественные аккаунты)

## 🧠 Варианты решения

### ❌ Что НЕ работает (пользователь легко обходит):

| Метод | Обход | Почему плохо |
|-------|-------|--------------|
| **Cookies** | Очистка cookies | ✅ Легко очистить |
| **LocalStorage** | Очистка site data | ✅ Легко очистить |
| **SessionStorage** | Закрытие вкладки | ✅ Очень легко |
| **IP Address** | VPN, мобильная сеть | ✅ Динамические IP |

---

### ✅ Что МОЖЕТ работать (устойчиво к очистке):

#### 1. **Browser Fingerprinting** (отпечаток браузера)
```javascript
// Уникальный ID на основе:
- User Agent
- Screen Resolution
- Timezone
- Language
- Canvas fingerprint
- WebGL fingerprint
- Audio context fingerprint
- Fonts list
```

**Библиотеки:**
- `@fingerprintjs/fingerprintjs` (бесплатная версия)
- `fingerprintjs-pro` (платная, точнее)

**Устойчивость:** 
- ✅ Не зависит от cookies/localStorage
- ✅ Работает даже после очистки
- ⚠️ Меняется при смене браузера/устройства

**Точность:** ~90-95%

---

#### 2. **Phone Number** (номер телефона)
```javascript
// SMS verification
1. Пользователь вводит номер
2. Отправляем SMS с кодом
3. Проверяем код
4. Создаём аккаунт
```

**Устойчивость:**
- ✅✅ Очень устойчиво (1 номер = 1 аккаунт)
- ✅ Реальная идентификация

**Недостатки:**
- ❌ Требует SMS сервис ($$$)
- ❌ Не "без email" концепция (но проще)
- ❌ Пользователи не хотят давать номер

---

#### 3. **Social OAuth** (без email requirement)
```javascript
// Telegram / Discord / Twitter
- Telegram Mini App authentication
- Discord OAuth (без email scope)
- Twitter OAuth (без email)
```

**Устойчивость:**
- ✅✅ Очень устойчиво
- ✅ Привязка к реальному аккаунту

**Недостатки:**
- ❌ Всё ещё требует аккаунт (не максимально просто)

---

#### 4. **Device ID + Browser Fingerprint** (комбо)
```javascript
// Гибридный подход:
1. Генерируем уникальный device ID (UUID)
2. Сохраняем в localStorage + IndexedDB + Cookie
3. Создаём browser fingerprint
4. ID пользователя = hash(deviceID + fingerprint)
5. Проверяем в БД: есть ли такой combo?
```

**Устойчивость:**
- ✅ Fingerprint работает после очистки
- ✅ DeviceID в 3 местах (сложнее удалить всё)
- ⚠️ Всё равно можно обойти (новый браузер)

---

#### 5. **Telegram Web App** (РЕКОМЕНДУЕМОЕ!)
```javascript
// Telegram Mini App:
1. Пользователь открывает через Telegram
2. Telegram автоматически передаёт:
   - telegram_id (уникальный)
   - username
   - first_name
3. Создаём аккаунт автоматически
4. Нет регистрации вообще!
```

**Преимущества:**
- ✅✅✅ **Максимально просто** (0 шагов)
- ✅✅✅ **100% защита** от абьюза (1 Telegram = 1 аккаунт)
- ✅✅ Без email
- ✅ Огромная база пользователей

**Недостатки:**
- ⚠️ Только для Telegram users
- ⚠️ Требует Telegram Bot API setup
