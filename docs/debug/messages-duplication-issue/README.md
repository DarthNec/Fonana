## 🐛 THE BUG

### User Experience:
1. User types "Hello" and clicks Send
2. Message appears at bottom of chat ✅
3. ~5 seconds later, message appears AGAIN ❌
4. User reloads page → Duplicate gone ✅

### Why It Happens:

```typescript
// Step 1: User sends message
sendMessage() → setMessages([...prev, newMessage]) // ← Manual add

// Step 2: 5 seconds pass...

// Step 3: Polling fires
loadMessages() → setMessages(allMessagesFromDB) // ← Overwrite

// Result: Message in state TWICE
```

## ✅ THE FIX (3 Changes)

### 1. Deduplicate Messages
```typescript
const deduplicateMessages = (messages: Message[]) => {
  const seen = new Set<string>()
  return messages.filter(msg => {
    if (seen.has(msg.id)) return false
    seen.add(msg.id)
    return true
  })
}
```

### 2. Check Before Adding
```typescript
setMessages(prev => {
  if (prev.some(m => m.id === data.message.id)) {
    return prev // Already exists, skip
  }
  return [...prev, data.message]
})
```

### 3. Reset Polling Timer
```typescript
clearInterval(pollingIntervalRef.current)
pollingIntervalRef.current = setInterval(...)
```

## 🎓 KEY LEARNINGS

### What Went Wrong:
- No deduplication logic
- Manual state updates + Polling = Race conditions
- Assumed React keys would handle duplicates (they don't)

### Best Practices for Future:
- ✅ Always deduplicate arrays by unique ID
- ✅ Use single source of truth (OR implement deduplication)
- ✅ Add integration tests for timing-sensitive features
- ✅ Consider WebSocket for real-time updates (long-term)
